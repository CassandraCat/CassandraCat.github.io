> 在小红书刷到 [@polebug](https://www.xiaohongshu.com/user/profile/) 的一份分享 (《保持思考｜等待｜斋戒——从后端开发到 AI 方向的学习经历和工作转变》)，第二部分讲企业里的 AI 工作分成三类，框架很清晰。这里把它记下来 + 加一点我自己的位置和体会。

## 三类方向

### 01 AI 基建

> 模型网关、用量统计、权限控制，让其他团队更低成本、更稳定地使用 AI。

这一层做的是**让 AI 能力变成一个可治理的内部资源**。具体形态：

- 模型网关（Gateway）：统一接入 OpenAI / Anthropic / 国内大模型，对上层屏蔽厂商差异
- 用量统计：按团队 / 项目 / 人 切分 token 消耗，月底出账
- 权限控制：哪些团队能用哪些模型、调用频率限制、审计日志
- 安全合规：敏感词过滤、PII 脱敏、合规审计

技术栈基本是后端（Go / Java / Python），跟传统 SRE / 中间件团队的活很像。区别是中间件守护的是 LLM API 这个"新基础设施"。

适合什么人：偏后端 / 平台 / 中间件背景，喜欢做被使用而不被看见的事。

### 02 内部 AI 工具

> 知识库问答、通用 workflow 平台、Skill hub、MCP 管理服务。

这一层做的是**给非 AI 团队提供开箱即用的 AI 能力**。具体形态：

- 知识库问答：把公司文档 / wiki / 飞书内容做成 RAG，员工自助查
- 通用 workflow 平台：低代码 / 可视化拼 AI agent 工作流（类似公司自己的 Dify / Coze）
- Skill hub：把可复用的 agent 能力（写 SQL、读图表、生成周报）做成内部 marketplace
- MCP 管理服务：内部工具用 MCP 协议接到 Claude Code / Cursor 等 IDE

技术栈是全栈 + LLM 应用层（LangChain / LlamaIndex / 自研 agent 框架）+ 一点前端。

适合什么人：偏全栈 / 产品工程，喜欢做"很多人用得到"的产品。这一层产品感比纯技术深度更值钱。

### 03 团队 AI 提效

> 了解业务，把团队经验沉淀成 Skill，并帮助它真正进入日常开发。

这一层做的是**进到具体业务团队里，把这个团队的工作流程 AI 化**。具体形态：

- 蹲业务：跟一线开发 / 测试 / 运维聊，看他们每天哪段时间在重复劳动
- 写 Skill：把流程封装成 Claude Code skill / Cursor rule / 自定义 agent
- 落地推动：让团队真用起来，量数据，迭代
- 经验沉淀：把"什么场景该用 AI 什么场景别用"的判断写下来

技术栈反而不是最重的——业务理解 + 沟通 + 推动力更难。会写 prompt、会拼 agent、会用 MCP，但更核心的是**懂这个团队为什么慢**。

适合什么人：偏业务 / 团队 leader / 乐于做 internal evangelism 的工程师。

## 我大概在哪

> 我目前做的事情，会更偏向第二类和第三类。
> ——polebug

把我自己的位置标一下：偏向 **02 + 03**，而且 03 的比重更大。

具体地：

- 给手上几个工程项目搭 AI 工具链是 02 的活——做内部 MCP server、设计 skill 模板、把日常常做的封装成可复用工作流
- 跟开发同事一起把这些工具落到日常开发里是 03 的活——不是给他们扔个工具说"你试试"，而是蹲下来看他们卡在哪、写一个具体到能直接用的 skill、看数据、迭代

01 的事情我不做。一是我们规模没到需要单独基建的程度（直接用厂商网关够了），二是我对纯后端基础设施的兴趣远低于"贴着业务做"的事。

## 这个分类的实用价值

读完这个框架最大的收获不是了解三类，而是**它强迫你看清自己每天在做什么**。

- 你的代码 95% 是写网关 / 配额 / 权限相关 → 你在 01
- 你的代码 95% 是写 RAG pipeline / agent 编排 / 平台化 → 你在 02
- 你的代码 95% 是给别人写 skill / 调 prompt / 推他们用 → 你在 03

跨类的人很少。三类的"成长方向"完全不同：

- 01 往技术深度走（性能 / 稳定性 / 大规模）
- 02 往产品感走（什么功能值得做 / 不值得做）
- 03 往业务理解 + 影响力走（怎么让别人变得更好）

如果你正打算往 AI 方向转，先别问"该学什么"，先问**"我想成为这三类里的哪一类"**。学的东西、积累的人脉、面试的简历重点，分歧很早就开始了。
