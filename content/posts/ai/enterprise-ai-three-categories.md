> 看企业里"做 AI"这件事，我观察下来大体是三类方向。每类背后的工作内容、技术栈、成长路径完全不同。如果你打算从某个方向转 AI，**搞清楚要去哪一类比"该学什么"重要得多**——三条路从一开始就分叉。

## 三类方向

### 01 AI 基建

模型网关、用量统计、权限控制，让其他团队更低成本、更稳定地使用 AI。

这一层做的是**让 AI 能力变成一个可治理的内部资源**。具体形态：

- 模型网关（Gateway）：统一接入 OpenAI / Anthropic / 国内大模型，对上层屏蔽厂商差异
- 用量统计：按团队 / 项目 / 人 切分 token 消耗，月底出账
- 权限控制：哪些团队能用哪些模型、调用频率限制、审计日志
- 安全合规：敏感词过滤、PII 脱敏、合规审计

技术栈基本是后端（Go / Java / Python），跟传统 SRE / 中间件团队的活很像。区别是中间件守护的对象是 LLM API 这个"新基础设施"——它跟数据库、消息队列在体系里是同一类位置：所有上层应用都依赖它，但理想状态下没人会感知它。

适合什么人：偏后端 / 平台 / 中间件背景，**喜欢做被使用而不被看见的事**。

### 02 内部 AI 工具

知识库问答、通用 workflow 平台、Skill hub、MCP 管理服务。

这一层做的是**给非 AI 团队提供开箱即用的 AI 能力**。具体形态：

- 知识库问答：把公司文档 / wiki / 飞书内容做成 RAG，员工自助查
- 通用 workflow 平台：低代码 / 可视化拼 AI agent 工作流（类似公司自己的 Dify / Coze）
- Skill hub：把可复用的 agent 能力（写 SQL、读图表、生成周报）做成内部 marketplace
- MCP 管理服务：内部工具用 MCP 协议接到 Claude Code / Cursor 等 IDE

技术栈是全栈 + LLM 应用层（LangChain / LlamaIndex / 自研 agent 框架）+ 一点前端。

适合什么人：偏全栈 / 产品工程，**喜欢做"很多人用得到"的产品**。这一层产品感比纯技术深度更值钱——能不能让一个不懂 AI 的运营/财务/HR 三步内用上你做的东西，是这一层的核心命题。

### 03 团队 AI 提效

了解业务，把团队经验沉淀成 Skill，并帮助它真正进入日常开发。

这一层做的是**进到具体业务团队里，把这个团队的工作流程 AI 化**。具体形态：

- 蹲业务：跟一线开发 / 测试 / 运维聊，看他们每天哪段时间在重复劳动
- 写 Skill：把流程封装成 Claude Code skill / Cursor rule / 自定义 agent
- 落地推动：让团队真用起来，量数据，迭代
- 经验沉淀：把"什么场景该用 AI 什么场景别用"的判断写下来

技术栈反而不是最重的——业务理解 + 沟通 + 推动力更难。会写 prompt、会拼 agent、会用 MCP，但更核心的是**懂这个团队为什么慢**。一个 skill 写得再优雅，业务团队不愿意用就是零分。

适合什么人：偏业务 / 团队 leader / 乐于做 internal evangelism 的工程师。

## 我自己在哪

我现在的位置是 **02 + 03**，而且 03 的比重更大。

具体地：

- **02 的活**：给手上几个工程项目搭 AI 工具链——做内部 MCP server、设计 skill 模板、把日常常做的封装成可复用工作流
- **03 的活**：跟开发同事一起把这些工具落到日常开发里——不是给他们扔个工具说"你试试"，而是蹲下来看他们卡在哪、写一个具体到能直接用的 skill、看数据、迭代

01 的事情我不做。一是当前业务规模没到需要单独基建的程度（直接用厂商网关够了），二是我对纯后端基础设施的兴趣远低于"贴着业务做"的事——我更愿意看到自己写的东西被一个具体的人天天用上，而不是默默支撑一个 SLA 数字。

## 这个分类的实用价值

这个三分法最大的好处不是给你一份"AI 工作清单"，而是**强迫你看清自己每天在做什么**。

- 你的代码 95% 是写网关 / 配额 / 权限相关 → 你在 01
- 你的代码 95% 是写 RAG pipeline / agent 编排 / 平台化 → 你在 02
- 你的代码 95% 是给别人写 skill / 调 prompt / 推他们用 → 你在 03

**跨类的人很少**。三类的成长方向完全不同：

- 01 往技术深度走（性能 / 稳定性 / 大规模）
- 02 往产品感走（什么功能值得做 / 不值得做）
- 03 往业务理解 + 影响力走（怎么让别人变得更好）

学习路径也不同：
- 01 该学的是 LLM Inference 优化、Token 计费精算、API Gateway 设计、合规
- 02 该学的是 RAG 工程化、agent 框架对比、产品调研、用户访谈
- 03 该学的是业务领域知识、prompt engineering 落地经验、跟人协作的功夫

如果你正打算往 AI 方向转，先别问"该学什么"——这个问题在你定位完之前没法答。**先问"我想成为这三类里的哪一类"**。简历重点、技能积累、人脉网，分歧从这里开始。

如果还在企业里没动过手，可以先做一个低成本验证：

- 想做 01 → 业余给团队搭一个简单的模型网关代理（哪怕只是 nginx + rate limit）
- 想做 02 → 给公司挑一个内部场景做一个最小知识库问答（哪怕只能回答一个 FAQ）
- 想做 03 → 找一个具体同事，蹲他工作流半天，给他写一个能直接用的 skill

哪条做下来你最不嫌烦，那就是你的方向。
